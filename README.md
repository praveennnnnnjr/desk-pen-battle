# Desk Battle: Pen Clash

A physics-based pen-flicking game for Android and iOS, built with **React Native (Expo)** and **Firebase**.
Pull back on your pen like a slingshot, release to flick it, and knock your opponent's pen off the desk.
First to 3 points wins — and the winner gets to challenge the loser with a question the loser *must* answer.

## Quick start (demo mode — no backend needed)

Requirements: Node.js 20+, and the **Expo Go** app on your phone (or an Android emulator / iOS simulator).

```bash
cd desk-battle
npm install
npx expo install --fix     # aligns native package versions with your Expo SDK
npx expo start
```

Scan the QR code with Expo Go. Without Firebase keys the app runs in **demo mode**:
accounts are stored on the device, and Multiplayer offers Pass & Play only. Single player vs AI and the full
post-game challenge flow work completely offline (AI questions come from a built-in question bank).

## Full setup (real accounts + online multiplayer + AI questions)

### 1. Create a Firebase project
1. Go to <https://console.firebase.google.com> → **Add project**.
2. **Build → Authentication → Get started → Email/Password → Enable.**
3. **Build → Firestore Database → Create database** (production mode, a region near your players, e.g. `asia-south1`).
4. **Project settings → Your apps → Add app → Web (`</>`)**. Copy the config values.

### 2. Configure the app
```bash
cp .env.example .env
```
Fill in the `EXPO_PUBLIC_FIREBASE_*` values, then restart with `npx expo start -c` (the `-c` clears the cache so new env values load).

### 3. Deploy security rules
```bash
npm install -g firebase-tools
firebase login
firebase use --add            # pick your project
firebase deploy --only firestore:rules
```
The rules ensure players can only touch their own matches, that only the winner can post the challenge, and
that only the loser can post the (single) reply.

### 4. (Optional) AI-generated challenge questions
Questions are generated by Claude through a Cloud Function, so the API key never ships inside the app.
Cloud Functions require the Firebase **Blaze** (pay-as-you-go) plan.

```bash
cd functions && npm install && cd ..
firebase functions:secrets:set ANTHROPIC_API_KEY     # paste your key from console.anthropic.com
firebase deploy --only functions
```
If you change the function region in `functions/index.js`, set the same value in
`EXPO_PUBLIC_FIREBASE_FUNCTIONS_REGION`. If the function is missing or slow, the app silently falls back to the
built-in question bank, so the game never gets stuck.

### 5. Test online play
Run the app on two devices (or a device + emulator), sign in with two different accounts, and tap
**Find online match** on both.

## How to play
- Touch your pen (it glows on your turn), drag **back**, and release. The dotted line shows where it will fly;
  the power bar shows how hard.
- Hit near the middle to push straight; hit near an end to make it spin.
- Knock the other pen off the desk → **you score**. Slide off yourself → **they score**. Both fall → round replays.
- After a point, the player who lost it shoots first in the next round.

## Customising the art
Replace the files in `assets/` (keep the names, or update `src/config/assets.js`):

| File | Notes |
|---|---|
| `desk.png` | Any desk/table image, stretched to a 2:3 area (1000×1500 ideal) |
| `pen_blue.png`, `pen_red.png` | Transparent PNG, pen lying **horizontally with the tip pointing right**, about 13:1 (e.g. 840×64) |
| `icon.png`, `adaptive-icon.png`, `splash.png` | App icon and splash screen |

Gameplay feel (power, friction, bounciness, AI strength, points to win) is all in `src/config/gameConfig.js`.
Colours are in `src/config/theme.js`.

## How online sync works
Matches are turn-based and **shooter-authoritative**. The shooter writes the exact starting positions and impulse;
the opponent replays the shot locally with the same deterministic physics, so both screens show the same animation.
When the shot settles, the shooter writes the final positions, score and next turn, and the opponent snaps to it —
so small floating-point differences between phones can never cause drift. Leaving mid-match forfeits it.

## Building for the stores
```bash
npm install -g eas-cli
eas build:configure
eas build -p android     # or -p ios
```
Change `ios.bundleIdentifier` and `android.package` in `app.json` to your own IDs first.

## Before going live — recommended hardening
- Turn on **Firebase App Check** and set `enforceAppCheck: true` in `functions/index.js` to stop abuse of the AI function.
- Add a per-user rate limit to the function and a profanity/moderation filter on chat messages if you open the game to the public.
- Add a turn timer for online matches so an idle player can't stall a game.
- Schedule a small cleanup job to delete old `matches` documents.
